# 設計判断

cmd/obsidian-searchはシグナルをcontextへ接続し、internal/searchcliがCLI入出力・Markdown解析・SQLite操作を担当します。具体型Storeを使い、インターフェースや追加サービス層は設けません。

通常テーブルfilesはVault相対パス、SHA-256、mtime、サイズを保存します。sectionsは原文範囲と本文を持ちます。ftsは内容を保持する通常のFTS5テーブルです。external contentの同期プロトコルを避け、sectionsのINSERT/DELETEトリガーで同期します。変更時はfilesの削除でsectionsを外部キーCASCADE削除し、再挿入します。全操作は同じトランザクションで確定します。旧行のUPDATE経路を作らないため、FTS更新の分岐を減らしています。

indexは1ファイルずつ処理し、既存パスとハッシュだけをメモリに保持します。mtimeだけでは同時刻・同サイズの変更を見逃すため、毎回ファイルを読みハッシュを確認します。再解析を省略することと、更新検出の正確性を優先します。DBへの書込みはimmediate transactionとbusy_timeoutで直列化します。プロセス内の接続数は1です。検索時は全Vaultを読みません。

FTSは検索語を二重引用符で囲み、内部の引用符もエスケープします。3文字未満の語はバインドしたinstr条件で検索し、長い語のFTS条件とAND結合します。短い語だけの場合にBM25を装うことはせず、score=0とします。パス絞り込みもLIKEではなくliteral prefix比較です。

原文の行範囲を再現するため本文はレンダリングせず保存します。見出しの構造だけGoldmarkを利用します。長いセクションの120行分割と200文字抜粋でエージェントの初回取得量を抑えます。showは行範囲で現在の原本を読みます。

スキーマバージョンはPRAGMA user_version=1です。未知の将来バージョンを拒否し、空DBからの初期化のみを提供します。破壊的な自動移行は行いません。

初期スキーマの作成とVaultへの紐付けも同じimmediate transactionで確定します。同時初期化による別Vaultへの二重紐付けを防ぎます。未知の非空DBを初期化しません。見出しの位置は行開始オフセットを使って二分探索し、見出しごとに全文を再走査しません。検索とスキーマは専用ファイルに分けています。showはDB設定から独立して原本を取得します。通常ファイル以外は非ブロッキングで開いて拒否し、FIFOによる停止を防ぎます。
